# PlanMark desktop (Windows) build

This is an Electron wrapper around the offline PlanMark web app in `/home/claude/pm-web`.
It builds a Windows x64 NSIS installer and a portable zip on Linux. You do not need wine.

## Rebuild

```bash
cd /home/claude/pm-desktop
./build.sh                         # copies /home/claude/pm-web -> ./web, then builds
WEB_SRC=/some/other/copy ./build.sh  # build from a different web folder
```

Outputs:
- `dist/PlanMark-Setup-1.0.0.exe` is the NSIS installer. It is per-user, lets you choose the install folder, and creates Desktop and Start Menu shortcuts named "PlanMark".
- `dist/PlanMark-1.0.0-win-x64.zip` is portable: unzip it and run `PlanMark.exe`.
- `dist/win-unpacked/` is the unpacked app. The web files are in `resources/app.asar` under `/web`.

`build.sh` copies whatever is in the web folder at the moment it runs. If `index.html` is
missing, the build fails. To change the version, edit `"version"` in `package.json`.

## How it works

- `main.js` serves `./web` over a privileged custom scheme, `app://planmark/`, which is
  registered as standard, secure, fetch-enabled, CORS-enabled and streamable. This lets
  pdf.js and tesseract Workers, `fetch()` and WASM work as they would over https.
  MIME types are set explicitly (`.js` is `text/javascript`, `.wasm` is `application/wasm`).
- Downloads use the native Save As dialog. The default name is the suggested filename and
  the default folder is Documents.
- Opening a PDF from "Open with", the command line, or a second launch is supported. A
  single-instance lock means a second launch hands its PDF to the window that is already
  running. A file passed at launch is held until the page registers its callback.
- Links to http(s) and mailto open in the default browser. Popups for `blob:` and `app:`
  URLs open in a new app window.
- There is no app menu, so Ctrl+S, Ctrl+O, Ctrl+Z and the rest go to the page.
  Ctrl+Shift+I or F12 opens DevTools.
- If the page cancels unload with `beforeunload`, PlanMark asks "Leave / Stay" instead of
  silently refusing to close.

### Preload API (`window.pmDesktop`)

```js
window.pmDesktop = {
  isDesktop: true,
  version: "1.0.0",          // app version from package.json
  onOpenFile(cb)             // cb({ name: string, bytes: Uint8Array })
};
```

### Building without wine

- `win.signAndEditExecutable: false` means rcedit and signtool are not used.
- `scripts/after-pack.js` uses `resedit` (pure JS) to write the icon and version info into
  `PlanMark.exe`.
- `scripts/build-win.js` runs electron-builder and makes it use its built-in pure-JS
  uninstaller extractor (`UninstallerReader`) instead of running the stub under wine.
  To do this, it overrides `isMacOsCatalina()`. This depends on electron-builder internals,
  so keep electron-builder pinned at 25.1.8.
- `build/icon.ico` is generated by `scripts/make-icon.py` (Pillow).

### "Open with" registration

`build/installer.nsh` adds, all under HKCU:
- a `PlanMark.pdf` ProgID
- `.pdf\OpenWithProgids`
- `Applications\PlanMark.exe\SupportedTypes`
- RegisteredApplications capabilities

It never changes the default value of `.pdf`, so PlanMark appears under "Open with" and in
Default apps but never becomes the default PDF handler. electron-builder's own
`fileAssociations` option was left out on purpose: its NSIS macro overwrites
`HKCU\Software\Classes\.pdf`'s default value. The uninstaller removes these keys.

## Caveats

- The exe and installer are unsigned. Windows SmartScreen will show "Windows protected your
  PC". Click **More info**, then **Run anyway**. To sign, set `CSC_LINK` and
  `CSC_KEY_PASSWORD` (this needs signing tooling) or sign on Windows afterwards.
- There is no auto-update (`publish: null`).
